# 박스웍스 안드로이드 앱 (1차)

웹 박스웍스 스케줄러를 안드로이드 앱으로 감싼 프로젝트입니다. 무엇을 만들지는 프로젝트 문서 `1차_범위.md`, 왜 그렇게 정했는지는 `결정_기록.md`를 따릅니다.

## 구조

| 위치 | 내용 |
| --- | --- |
| `web-src/boxworks.html` | 웹 박스웍스 원본(claude.ai 아티팩트에서 가져옴). 여기서는 직접 고치지 않음 |
| `web-src/app-shim.js` | 앱 연결부. 웹 박스웍스가 쓰던 Claude 기능 자리를 휴대폰 기능으로 채움 |
| `scripts/build-web.mjs` | 원본을 앱용 `www/index.html`로 바꿈. 바꿀 곳을 못 찾으면 멈춤 |
| `android/` | Capacitor가 만든 안드로이드 프로젝트 |
| `.github/workflows/android.yml` | GitHub에서 시험판 설치 파일을 자동으로 만듦 |

## 지금 앱이 하는 일

- 웹 박스웍스 화면과 기능을 그대로 씀. 일정은 휴대폰 안에 저장(서버·로그인 없음, D-02)
- **휴대폰 알람(2단계)**: 박스웍스 알림 규칙으로 앞으로 7일 알람을 계산해 `BxAlarm` 플러그인이 휴대폰에 예약. 잠금 화면 알람 화면(`AlarmActivity`), 알림의 확인·5분 뒤, 재부팅·업데이트 뒤 다시 예약(`BootReceiver`)
- **말로 넣기(3단계)**: `BxSpeech` 플러그인이 휴대폰 기본 음성 인식을 열고, 받은 글자를 박스웍스 규칙 해석에 넣음. 규칙 보강은 `scripts/build-web.mjs`의 `bxQuickPre`·`bxQuickFix`
- **시간표(D-06)**: `web-src/timetable.js`. 아래 메뉴의 시간표 탭, 한 문장 해석(`ttParse`), 시작 전 알람, 오늘 화면 카드
- **출발 시각 계산·준비 루틴(4단계)**: `web-src/travel.js`. "가는 데 30분" 해석, 출발 10분 전·출발 알람, 장소별 이동 시간 기억(`travelmem` 문서), 일정에 루틴 붙이기(출발 시각에서 거꾸로)
- **휴대폰 캘린더 읽기(D-05)**: `BxCalendar` 플러그인(읽기 전용, READ_CALENDAR)과 `web-src/calendar.js`. 읽은 일정은 화면에만 섞어 보여 주고, 박스웍스에서 정한 알림·이동 시간·완료는 `pcx` 문서에 따로 적음
- 앱에서 쓰지 않는 웹 전용 기능(Claude 연동, AI 정리, 위젯 모드, 바로가기 설치 안내)은 숨김
- 휴대폰 뒤로 버튼: 열린 창 → 앞 창 → 오늘 화면 → 앱을 뒤로 보냄

아직 없는 것: 아침 보고, 홈 화면 위젯, 루틴을 말로 고치기("샤워 30분으로")

## 설치 없이 화면 확인하기

`npm run build:web && node scripts/build-preview.mjs <파일>`로 앱 화면을 한 파일로 만들어 claude.ai 페이지로 올린다. 휴대폰 브라우저에서 열면 앱과 같은 화면이 나오고, 알람·마이크·휴대폰 캘린더만 동작하지 않는다(안내만 뜸). 화면·문구·정렬은 여기서 보고, 휴대폰 기능을 바꾼 때만 설치 파일로 확인한다.

## 시험판 만들기

`main`에 올리면 GitHub Actions가 설치 파일을 만들어 **Releases**에 `시험판 N`으로 올립니다. 결과(성공·실패, 오류 내용, 설치 파일)는 `ci-results` 브랜치에도 남아서 저장소가 비공개여도 git으로 받을 수 있습니다. 휴대폰에서 그 페이지를 열어 apk를 받아 설치합니다. 처음 한 번은 "출처를 알 수 없는 앱 설치"를 허용해야 합니다.

시험판마다(통합관리실): ① 와이어프레임 수정 지시(그 페이지 db `notes`, status `open`)와 결정 사안의 '결정 · 반영 전'을 먼저 읽어 이번 시험판에 넣을 것을 정한다 ② 자동 시험 · 정렬 점검(폭 360 · 384 · 412 × 라이트 · 다크 × 시각 표시 둘)을 통과해야 올린다 ③ 바뀐 화면 전후 사진(폭 384) · 와이어프레임 새로 올리기 ④ 고친 수정 지시는 `done` · `doneIn` · `doneNote`로 바꾼다(아래 '와이어프레임 수정 지시')

직접 만들 때(Android Studio가 있는 컴퓨터):

```
npm ci
npm run sync
cd android && ./gradlew assembleDebug
```

## 첨부 · 백업 (시험판 42)

- 일정 첨부는 `BxAttachPlugin`(사진 선택기 · 카메라 앱 · 파일 창, 권한 없음)이 `files/attach/`에 복사한다. 사진은 긴 변 2048px JPEG + 작은 그림(`_t.jpg`). 화면 코드는 `web-src/v42.js`
- 백업 파일은 첨부가 있으면 zip(`boxworks.json` + `attach/…`, 압축 없이), 없으면 json. 불러오기는 둘 다
- 구글 자동 백업은 `res/xml/bx_data_extraction.xml`(12 이상) · `bx_backup_rules.xml`(11 이하)에서 `attach/`를 뺀다. 앱 하나 25MB를 넘으면 일정까지 백업이 멈추기 때문

## 캘린더 보기 (시험판 43)

- 왼쪽 아래 작은 '일 · 주 · 월'(`#bx-vsw`)이 보기를 바꾼다. 위의 월간 · 주간 줄은 앱에서 뺐다(웹은 그대로). 코드는 `web-src/v43.js`, 화면 길은 `scripts/patches-v43.mjs`
- `bxCalFit`이 화면 높이에 맞춰 날짜 칸 높이(`--bx-cell-h`)와 칸마다 일정 줄 수(2~4)를 정한다
- '일'은 캘린더 안 하루 보기(`bxDayViewHtml`, `S.view = 'day'`). 휴대폰 뒤로 단추는 일 → 월

## 일정 창 · 명상 소리 (시험판 44)

- 일정 창은 삼성 캘린더 방식 줄 목록이다(`web-src/v44.js`의 `bxEdList`). 줄을 누르면 페이지(`#bx-ep`)가 열린다. 원래의 고르는 칸(`#f-panel`)을 페이지로 옮겨 쓰고, '완료'는 그대로 두고 ‹ · 휴대폰 뒤로는 연 순간의 값(`bxEpSnap`)으로 되돌린다
- 명상 소리 크기: `BxSound.setVolume({bell, bg})` → `SoundPrefs`(기기 보호 저장소). `BowlPlayer` · `BgPlayer`가 소리에 곱한다
- 앱을 최근 목록에서 지우면 배경 소리와 남은 명상 종을 멈춘다(`BxSoundService.onTaskRemoved`, `MainActivity.onDestroy`). 앱은 `BxSound.status().medCancel`을 보고 '명상 중' 화면을 치운다
- 배경 소리 없이 종만 쓰는 명상은 소리 서비스가 없어 최근 목록에서 지운 순간을 모른다. 그래서 명상 종(`med_` 알람)이 울릴 때 앱 카드가 남아 있는지(`MainActivity.hasTask`, `ActivityManager.getAppTasks`) 보고, 없으면 울리지 않고 남은 종을 지운다(시험판 47)

## 수업 창 · 휴대폰 캘린더 일정 창 · 루틴 고치기 (시험판 45)

- 같은 삼성 방식을 다른 입력 창에도 쓴다(`web-src/v45.js`). 페이지는 시험판 44의 `bxPgOpen(제목, 칸, 되돌리기)`: 창 안에 숨겨 둔 칸을 페이지로 옮겨 쓰고, 닫으면 제자리로 돌려놓는다
- 수업 창(`ttDraw`): 저장은 예전처럼 `#tt-name` · `#tt-start` · `#tt-end` · `#tt-place` · `#tt-rem-c` 칸을 읽는다. 장소 · 알림 · 시간표는 숨긴 칸(`.bx-tt45-hold`)에 있다가 페이지로 간다
- 휴대폰 캘린더 일정 창(`pcDraw`): 고르면 바로 `px_…` 문서에 적히므로, ‹ 는 연 순간의 문서 · 이동 시간 기억(`travelmem`) · 막 만든 '외출 준비'를 되돌린다
- 루틴 고치기(`bxDrawRoutine`, `rtTimesHtml`): 알림 방식 · 기준은 페이지, 시각 줄은 기준에 따라 시작 시각 하나 또는 도착 시각 · 이동 시간 · 여유

## 확인 필요 날짜 변경 (시험판 46)

- '날짜 변경'(`bxLatePickDate`)은 카드 안에 칸을 펼치지 않고 페이지를 연다(`web-src/v46.js`). 페이지 안의 `#bx-lc-date` · `#bx-lc-time`과 숨은 `data-bx-late="move"` 단추를 쓰므로, 옮기는 일은 예전 '변경' 단추 처리(`flow.js`)가 그대로 한다. '완료'를 누르면 그 단추를 누른 것과 같다

## 명상 끝내기 · 메모 화면 · 위젯 → 홈 (시험판 48)

- 명상하는 동안 알림창 · 잠금 화면에 '명상 중 · N분' 알림 한 장(남은 시간을 거꾸로 셈, '명상 끝내기' 단추). 휴대폰 쪽은 `MedOngoing`(채널 `bx_med_v1`). 배경 소리가 나오면 소리 서비스(`BxSoundService`)의 알림이 같은 모양으로 대신해 알림이 두 장이 되지 않는다. 그래서 앱은 `BxSound.medOngoing({startAt, endAt, min, bg, bell})`을 배경 소리를 틀기 **전에** 부른다(`web-src/v48.js`)
- '명상 끝내기'는 `AlarmActionReceiver`(`med-stop`) → `MedOngoing.stopAll`: 남은 명상 종 · 배경 소리 · 울리는 종을 멈추고 `SoundPrefs.medCancel`을 적는다. 앱이 살아 있으면 `medStop` {at}을 알려 '명상 중' 화면을 바로 치우고, 끝낸 시각까지 한 만큼 기록한다
- 앱 안에서도 명상 화면이 아닌 곳이면 아래 메뉴 위에 '명상 중 · 남은 시간 · 끝내기' 줄(`#bx-medbar`). 시간표에서는 아래 도구 줄 위. 줄이 있는 동안 + 단추 · 일 · 주 · 월 · 알림 글은 그만큼 위로
- 호흡 안내: 원 뒤 꽃잎 여섯 장(`.bx-med-fl`)이 들이쉴 때(4초) 피고 내쉴 때(6초) 오므린다. 시작 전 5초 동안은 지연(`--bx-bd`)을 양수로 둬 첫 종과 함께 피기 시작한다
- 메모 화면은 적은 메모만. + 단추(캘린더와 같은 단추, `data-bxmemo`) → '새 메모' 페이지(`#bx-mmn`, ‹ 는 적지 않고 닫기 · 완료는 저장)
- 위젯 단추(✎ · 🎤 · + · 앱 열기 · 일정 줄)로 들어오면 먼저 홈 화면(`BX_goHome`). '앱 열기' · 위젯 누르기는 새 동작 `kr.boxworks.app.W_HOME`(`BxWidgetPlugin`의 'home')
- 휴대폰 캘린더 일정은 테두리 칸이 아니라 그 캘린더 색으로 그린다. 칩 줄 위에서는 달 넘기기(옆으로 밀기)를 하지 않는다(`home.js`)

## 홈 줄 · 날짜 달력 · 일정 창 · 명상 배경 그림 (시험판 49)

- 일정 줄(`rowHtml`, `web-src/v49.js`)은 원래 줄을 만든 뒤 줄이기만 한다: 남기는 것은 날짜 · 여러 날 · 지남 · 진행 중 · 곧 시작 · 장소(글자만) · 첨부 표시. 오른쪽 칸 `.bx-r49-go`는 `tvPlan`의 출발(없으면 준비) 시각
- 날짜 페이지 달력(`.bx-dcal`): 한 번 누르면 그날(`F.multi` 끔), 이어서 뒤의 날을 누르면 그날까지(`F.multi` · `F.endDate`). 페이지를 새로 열면 첫 누름은 다시 '그날'. 원래 날짜 칸 · 끝나는 날 칸은 숨기고 그대로 둔다(저장은 예전 처리)
- 일정 창: 제목 옆 `.bx-tdot`(누르면 캘린더 페이지), 아래 `.bx-pill49`('취소'는 `sheet-close`, '저장'은 원래 단추를 옮긴 것), 고치기의 '삭제'는 줄 목록 맨 아래 `.bx-er-del`
- 명상 배경 그림(`web-src/v50.js`): 배경 소리마다 SVG · CSS로 그린 장면(`BX_SCENES`). 다시 그려도 튀지 않게 앱을 연 때부터의 시간(`--t`)만큼 애니메이션을 앞당긴다

## 디자인 가이드: 보라 · 글자 6단계 · 오전 · 오후 (시험판 51)

기준은 Design System 문서 '박스웍스 디자인 가이드'(결정 기록 D-24). 새 화면은 이 세 가지를 지킨다.

- **색**: `--accent`(#7C3AED, 라이트 · 다크 같음)는 채운 것에만 쓰고 그 위 글자 · 아이콘은 `--accent-ink`(흰색). 바탕 위 보라 글자 · 선은 `--accent-text`(다크 #A98BFA). CSS에 `color:var(--accent)`를 쓰지 않는다. 휴대폰 쪽: 위젯 `bx_w_*`, 알림 `setColor`, 잠금 화면 알람, 앱 아이콘(`ic_launcher_foreground_bx`)
- **글자 크기**: 28 · 20 · 16 · 14 · 13 · 11.5만. `scripts/build-web.mjs`가 마지막에 모든 `font-size:Npx`를 가장 가까운 단계로 맞춘다(명상 타이머 숫자 50 · 38만 따로). 휴대폰 쪽 글자(sp)도 같은 단계
- **시각**: 화면 · 알림 글은 `bxT('15:00')` → '오후 3:00', 두 시각은 `bxTR(a, b)` → '오후 3:00–4:00'(오전 · 오후가 같으면 뒤를 줄임), 시(時)만은 `bxH(9)` → '오전 9시'. 저장 값과 계산은 그대로 'HH:MM'. 화면 글에서 시각을 다시 읽을 때는 `bxHMAll`(오전 · 오후를 안다). 원본 · 앞 패치의 글은 `scripts/patches-v51.mjs`가 바꾼다(다른 패치가 끝난 뒤의 글자를 찾음)
- 시각 입력 칸(`input type=time`)은 `web-src/v51.js`가 칸 위에 '오후 3:00'을 그리고 칸을 투명하게 위에 둔다(값 · id · 휴대폰 시각 창은 그대로). 휴대폰 쪽은 `SimpleDateFormat("a h:mm", Locale.KOREA)`

## 루틴 단계 세기: 꼭 울림 · 짧게 한 번 · 소리 없이 (시험판 52)

결정 기록 D-25(대표 11/4 16:58 "건건이 확인을 눌러야 꺼지는 알람은 스트레스, 가볍게 울려 주면서 지금쯤 씻기를 해야 하는구나"). 루틴은 폰을 쥐고 있지 않아도 되게 한다.

- **자료**: 단계의 `ring`('must' | 'short')은 사용자가 고른 때만 남는다. 소리 없이는 지금처럼 `kind: 'wait'`. 고르지 않은 단계는 `bxStepRing`(web-src/v52.js)이 정한다: 첫 단계 · 중요한 단계(`chk`, 시험판 68)는 꼭 울림, 나머지는 짧게 한 번(이름으로 정하지 않음). 출발 줄은 늘 꼭 울림이고 확인 단추는 '다 했어요'
- **알람 계획**(`BX_alarmPlan`): 꼭 울림 = 울리는 방식(`bxLevel('routine')`) + 다시 알림(다음 꼭 울림 단계 전까지, 짧게 한 번 단계가 끼어 있어도 이어짐). 짧게 한 번 = `lv: 'short'` 한 번(울리는 방식이 '조용히'면 `silent`). 같은 시각에 꼭 울림이 있거나 0분 단계로 시각이 같으면 하나만. 기다리기 시작 = `lv: 'silent'`(알림 없이 진행 알림 · 위젯만, 상태 표시줄 '다음 알람'에 넣지 않음). 확인 안 한 단계 알림(rcheck) · 홈 주의 줄 · 빨간 숫자는 중요한 단계만(시험판 67까지는 약 단계)
